# 简历助手提示词与资料边界

## 回答规则

`apps/api/src/prompts.ts` 分别维护身份与范围、事实与隐私、选材与顺序、资料与引用规则；`chat-style.ts` 维护面向访客的表达方式。通用规则不重复维护项目选型、接口数量、参与阶段等事实，这些仍以根简历和批准的项目知识为准。

通用能力问题默认一句结论加最近的一个相关例子，通常 120–220 字、两到三个自然段，必要时才补第二例。涉及多段任职时按时间倒序，字节跳动先于 AFFiNE 等更早经历；明确指定公司、项目或比较顺序时遵循问题范围。指代式追问继承相关上下文，重新询问通用能力则重新选材。

已有事实用“负责、参与、与团队共同完成”自然表述。共同作者、统计口径和职责边界仍保留在知识库；只有问题涉及独立性、证据、成果归因或核心信息缺失时，才展开相应说明。数字、阶段交付和团队成果的必要限定不能为了简短而省略。明确要求详细实现、定位或比较时允许展开，不机械截断答案。

提示词附有协作、选型、资料不足三个表达示例；示例仅演示答法，不能取代当前资料或扩展提问范围。协作示例依据字节知识第 5.1 节，拖拽选型示例依据 AFFiNE 第 6 节已批准问答。批准知识变化后需复核示例，不能把示例当作另一份履历事实来源。

## 请求消息

DeepSeek 请求由 `buildChatMessages` 统一构造：

1. 一条 system 消息：通用规则、表达规则与示例、完整的批准公开知识。
2. 访客原有历史消息，顺序和内容均不改写。
3. 有仓库读取结果或失败记录时，插入一条 user 角色 JSON 数据消息，`type` 为 `untrusted_repository_reference`。其中 `repositories` 包含成功读取的 README、来源提交、截断及快照信息，`unavailable` 只表示本次读取失败。
4. 当前访客问题原样放在最后。

空仓库上下文不插入占位轮次。引用资料消息仅存在于本次上游请求，不写成访客历史，也不授权模型执行仓库中的指令。对外接口仍只接收既有 user/assistant 消息格式，不开放客户端 system 角色。来源链接继续来自实际读取结果；失败仓库不伪造成功来源。

只有经过批准、版本化的简历和项目知识进入 system；原始聊天、归档证据和外部 README 不因此获得相同可信度。`PROMPT_VERSION` 覆盖规则、风格、示例和引用消息类型，知识版本与发布提交仍独立标识来源。

## 验证和限制

消息边界回归测试位于 `apps/api/test/prompt-context.test.ts`，并与既有 prompts、chat、GitHub 测试共同校验历史、问题、来源、脱敏和流式契约。真实模型检查单独执行，不在 CI 中调用付费模型；测试时仅使用公开问题和模拟仓库注入样本。

消息角色和 JSON 数据分层降低外部内容污染 system 的风险，不保证模型绝不受注入影响。回答长度、选材和语气属于模型行为约束，需要以真实问答抽样验证；不能将字符串断言通过当作回答质量证明。

## 详细追问预算

`API_CHAT_MAX_TOKENS` 默认与最大值均为 10000，思考和可见正文共享该输出上限；这不是每轮固定消耗量，也不要求普通回答变长。通用问题仍遵循简短表达，明确的实现细节追问可以展开。后端单次请求默认超时为 120 秒，前端总等待上限 125 秒，30 秒空闲保护仍保留；服务端思考期间发送心跳，访客仍可随时停止。

本地抽样曾出现 1024 token 未输出正文、2048 token 输出约 580 字后以 `length` 结束；提高预算后应同时检查正文完整性和 `finishReason=stop`，不能只看 HTTP 状态。模型每次思考量不同，上限不保证所有复杂问题都能完整回答。仍保留请求并发、每日次数、字符大小和时间限制。历史中的用户问题最多 4000 字符、完整回答最多 16384 字符，总上下文最多 32768 字符；前端按完整轮次取最近历史，避免详细回答超过 4000 字符后下一轮丢失上下文。

费用按实际上游 usage 和供应商当前单价计算，不能仅从中文字数推算。官方参数与计费说明：[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。已有部署环境的显式环境变量优先于代码默认值，需在后续获准部署时同步调整；修改样例配置不代表线上已生效。
